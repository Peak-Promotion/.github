# Contributing to Peak Promotion

Thanks for helping out. A few rules keep the work safe and easy to review.

## How to work

1. Fork the repository (button at the top right) and work in your fork.
2. Make one branch per task, for example `fix/segment-touch-target` or `feat/showcase-toast`.
3. Keep pull requests small: one task per pull request.
4. Open the pull request against `main`, or against the branch named in the issue, and fill in the template.

## Rules

- Never commit secrets: no `.env` or `.dev.vars` files, API keys or tokens. Settings live in Cloudflare.
- No real client data. Use the example data that is already in the repository.
- Run the tests before you open a pull request (`npm test`).
- Something unclear? Ask in the issue. Asking is better than guessing.

## Reviews

Every change is reviewed before it is merged. Questions and requested changes are normal; they are how we keep the quality up.
